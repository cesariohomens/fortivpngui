# FortiVPN GUI v0.4.0

**FortiVPN GUI** is a **Linux** desktop VPN client built with **Electron**, **React**, and **Material UI**. It drives **FortiGate** tunnels via the system **`openfortivpn`** binary. Configuration under **`~/.fortivpngui/`** uses an **INI-style layout** compatible with **OpenFortiGUI** (profile/group import and optional `main.conf` merge).

## Highlights

### New in 0.4.0

- **FortiGate only.** Barracuda / `barracudavpn` support is removed; the product focuses on `openfortivpn`.
- **Themed scrollbars.** Native browser scrollbars are replaced with **OverlayScrollbars** styled for light and dark themes, including axis arrow buttons.
- **Custom dialogs for copy and delete.** Native `prompt()` / `confirm()` are replaced with the same MUI modals used elsewhere; after duplicating a VPN the new profile opens in the editor.
- **Reconnect interval** lives under **Options → Advanced** (full width), not Common.
- **`openfortivpn` options that never reached the binary are fixed:**
  - **Set DNS** and **Accept remote** are written explicitly when unchecked (upstream defaults them to on).
  - The old **No peerdns** checkbox wrote the invalid config key `pppd-no-peerdns`, which made `load_config()` abort and discard every later key (PPPD + OTP settings). It is now **Use peerdns** → `pppd-use-peerdns = 0|1`.
- **New profile options:** PEM pass phrase, Cipher list, SNI, User-Agent, Host check, Virtual desktop check, plus **SAML login** (browser opens automatically), **SVPNCOOKIE** (stdin), **pinentry**, **bind to interface** (`--ifname`), and **use resolvconf**.
- **Per-version / `--help` gating.** Keys the installed `openfortivpn` cannot parse are omitted and reported in the VPN log instead of truncating the config.
- **Cache clean on start.** `npm start` runs a cache wipe before build; `npm run clean` is available alone.
- **Automated screenshots** for the README (`npm run screenshots`), captured in both **dark** and **light** themes.
- **Dead fields removed** from profiles / `main.conf`: unused `verify_cert`, `otp`, `initd`, and `sudopresenv`.

### Upgrade notes

- Existing profiles with `persistent = true` (or `1`) still map to **60 seconds**.
- The old `pppd_no_peerdns` INI key never reached `openfortivpn`; profiles load with **Use peerdns** off. The inverted key is still written for OpenFortiGUI compatibility.
- Unchecking **Set DNS** now really disables `set-dns`.
- `verify_cert` is no longer written to profile INI files; `initd` / `sudopresenv` are no longer written to `main.conf`.

### From 0.3.0

- No silent auto-reconnect by default; configurable `persistent` interval; disconnect warning dialog; RPM packages alongside `.deb`.

See [v0.3.0](v0.3.0.md), [v0.2.1](v0.2.1.md), and [v0.2.0](v0.2.0.md) for earlier notes.

## Requirements

- **Linux** with `openfortivpn`, `ppp`, and `sudo`.
- **`.deb` install**: also **`libsecret-1-0`** for optional OS credential storage.
- **`.rpm` install**: also **`libsecret`** for optional OS credential storage.

## Install

### Debian / Ubuntu

```bash
sudo apt install ./fortivpngui_0.4.0_amd64.deb
```

### Fedora / RHEL

```bash
sudo dnf install ./fortivpngui-0.4.0.x86_64.rpm
```

### openSUSE

```bash
sudo zypper install ./fortivpngui-0.4.0.x86_64.rpm
```

Then review or tighten the sudoers drop-in if needed:

```bash
sudo visudo -f /etc/sudoers.d/fortivpngui
```

## Build from source

```bash
npm ci
npm run dist        # .deb + .rpm
npm run dist:deb    # .deb only
npm run dist:rpm    # .rpm only (needs rpmbuild / rpm-build installed)
```

Artifacts are written to `release/`.
