# FortiVPN GUI v0.5.1

**FortiVPN GUI** is a **Linux** desktop VPN client built with **Tauri 2** (Rust), **React**, and **Material UI**. It drives **FortiGate** tunnels via the system **`openfortivpn`** binary. Configuration under **`~/.fortivpngui/`** uses an **INI-style layout** compatible with **OpenFortiGUI**.

## Highlights

### Fixed in 0.5.1

- **OTP dialog only appeared after Stop.** `openfortivpn` prints the token prompt (`Two-factor authentication token:`) with `printf` + `fflush` and **no trailing newline**, then blocks on stdin. The Tauri runner read output line by line, so the prompt never surfaced until the process exited — the dialog opened too late and sending the token failed with *"Could not send the token (no active VPN process for this profile)"*. Output is now read in chunks: an unterminated OTP prompt is surfaced as soon as it arrives, the main window is brought forward, and the fragment is not duplicated when the line completes.
- **Request new OTP after a rejected token.** `openfortivpn` exits after a wrong code, so there was no stdin to write to. The button now reconnects **without** a token when the process is gone; the gateway issues a fresh code (e.g. by email) and the stdin prompt reopens the dialog. When the process is still running (`persistent` reconnect), the previous behaviour is kept.
- **Stale authentication failures.** Old `Could not authenticate to gateway` log lines no longer flip the dialog into the *OTP failed* state right after a new submission.

### Packaging

- **Flatpak** bundle built from the Tauri `.deb` (`npm run dist:flatpak`, manifest under `flatpak/`). `npm run dist` now produces `.deb`, `.rpm`, AppImage, and Flatpak.
- The Vite build output (`dist/`) is no longer tracked in the repository; it is regenerated by the Tauri `beforeBuildCommand`.

### From 0.5.0

- Tauri 2 / Rust desktop shell replacing Electron, same React / Material UI renderer, OpenFortiGUI-compatible config, keyring-based password store.

## Requirements

- **Linux** with `openfortivpn`, `ppp`, and `sudo`.
- **Development**: Node.js **20+**, npm, **Rust** (stable), and Tauri system libs (`webkit2gtk-4.1`, `gtk3`, `librsvg`, `openssl`).
- **`.deb` install**: also **`libsecret-1-0`** for optional OS credential storage.
- **`.rpm` install**: also **`libsecret`** for optional OS credential storage.
- **Flatpak**: host `openfortivpn`, `ppp`, and `sudo` (the VPN helper runs outside the sandbox); install the sudoers drop-in on the host.

## Install

### Debian / Ubuntu

```bash
sudo apt install ./fortivpngui_0.5.1_amd64.deb
```

### Fedora / RHEL

```bash
sudo dnf install ./fortivpngui-0.5.1-1.x86_64.rpm
```

### openSUSE

```bash
sudo zypper install ./fortivpngui-0.5.1-1.x86_64.rpm
```

### AppImage

```bash
chmod +x fortivpngui_0.5.1_amd64.AppImage
./fortivpngui_0.5.1_amd64.AppImage
```

### Flatpak

```bash
flatpak install --user ./fortivpngui_0.5.1_x86_64.flatpak
flatpak run com.cesariogarcia.fortivpngui
```

Then review or tighten the sudoers drop-in if needed:

```bash
sudo visudo -f /etc/sudoers.d/fortivpngui
```

## Build from source

```bash
npm ci
npm run dist           # .deb + .rpm + AppImage + Flatpak
npm run dist:deb       # .deb only
npm run dist:rpm       # .rpm only (needs rpmbuild)
npm run dist:appimage  # AppImage only (needs appimagetool + squashfs-tools)
npm run dist:flatpak   # Flatpak only (needs an existing .deb + flatpak-builder)
```

Artifacts are written under `src-tauri/target/release/bundle/`.
