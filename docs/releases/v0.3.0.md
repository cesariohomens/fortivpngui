# FortiVPN GUI v0.3.0

**FortiVPN GUI** is a **Linux** desktop VPN client built with **Electron**, **React**, and **Material UI**. It drives **FortiGate** tunnels via the system **`openfortivpn`** binary. Configuration under **`~/.fortivpngui/`** uses an **INI-style layout** compatible with **OpenFortiGUI** (profile/group import and optional `main.conf` merge).

## Highlights

### New in 0.3.0

- **No silent auto-reconnect.** Earlier versions always wrote `persistent = 60` into the generated `openfortivpn` config, so a dropped tunnel was retried every minute without telling the user. Reconnecting is now the **user's decision** by default.
- **Reconnect interval is configurable per profile.** The `openfortivpn` **`persistent`** option is exposed in the VPN editor (**Options → Advanced → Reconnect interval (seconds)**). Leave it **empty** or **`0`** to disable automatic reconnection; set any positive number of seconds to keep the old retry behaviour.
- **Disconnect warning dialog.** When a tunnel drops without the user asking for it, a **Warning** dialog (styled like the **About** modal) explains **why** and shows the **last log lines**. Detected reasons:
  - authentication rejected by the gateway
  - invalid or expired one-time password
  - gateway certificate could not be validated
  - gateway unreachable (DNS, routing, firewall)
  - connection timed out
  - connection reset / closed by the gateway
  - `pppd` failure
  - `sudo` refused to run `openfortivpn`
  - VPN helper binary missing
  - generic tunnel-down and unknown causes
- **User-initiated disconnects stay silent** — stopping a VPN from the UI, the tray, or on quit does not raise the warning.
- **RPM packages** are now produced alongside **`.deb`** (**Fedora**, **RHEL**, **openSUSE**), with dedicated RPM scriptlets (`%post` / `%postun` semantics), `libsecret` dependency, and `restorecon` labelling for SELinux systems.
- **Warning dialog and reconnect setting are fully translated** in all six shipped languages (English, Portuguese, Spanish, French, Italian, German).
- **Reconnect interval field** no longer shows the long openfortivpn helper paragraph under the control.
- **Editor options now actually reach `openfortivpn`.** Three profile options were silently ineffective:
  - **Set DNS** and **Accept remote** were only written when enabled, while `openfortivpn` defaults them to *on* (`set_dns = 1`; `pppd_accept_remote = 1` for pppd ≥ 2.5.0). Unchecking them did nothing. Both values are now written explicitly.
  - **No peerdns** wrote `pppd-no-peerdns`, which is a **command-line flag only** — not a config-file key. `load_config()` aborts at the first key it does not recognise, so every option after it was discarded without an error: the whole **PPPD** section plus **OTP prompt string**, **OTP delay** and **No FortiToken Mobile push**. The checkbox is now **Use peerdns** and writes `pppd-use-peerdns = 0|1`.
- **New profile options.** **PEM pass phrase** (Certificate section, stored encrypted like the password), **Cipher list** (SSL section — upstream recommends it over **Insecure SSL** when a gateway demands a specific cipher), and a new **Gateway compatibility** section with **SNI**, **User-Agent**, **Host check** and **Virtual desktop check**.
- **Per-version option gating.** Options that the installed `openfortivpn` is too old to parse are omitted instead of breaking the config, and the skipped keys are reported in the VPN log. Minimum versions: `min-tls`/`seclevel-1`/`pinentry` 1.10, `use-resolvconf` 1.14, `pem-passphrase`/`user-agent`/`hostcheck`/`check-virtual-desktop` 1.16, `pppd-accept-remote` 1.21, `sni` 1.22, `saml-login` 1.23. Command-line-only options are checked against the binary's own `--help` instead, since an unknown argv option would make `openfortivpn` exit.
- **Every remaining `openfortivpn` option is now in the editor:**
  - **SAML login** (`--saml-login`, with a configurable redirect port). `openfortivpn` logs `Authenticate at '<url>'`; FortiVPN GUI opens that page in the default browser and shows a toast, so the browser round-trip works without watching the log.
  - **SVPNCOOKIE** (`--cookie-on-stdin`), fed on stdin rather than argv so the session cookie never shows up in the process list. The config-file `cookie` key is explicitly ignored upstream, so argv is the only option.
  - **Pinentry program** (`pinentry`), to have the password asked at connect time instead of stored.
  - **Bind to interface** (`--ifname`), which is command-line only and distinct from the PPPD **Ifname**.
  - **Use resolvconf** (`use-resolvconf`) as a three-state control: default, enabled, disabled.
  - A username is no longer required when a cookie or SAML login is configured, matching `openfortivpn`'s own argument check, and the FortiGate token dialog stays closed for those profiles since they never prompt for one.
- **Options deliberately left out**, because they conflict with a GUI rather than being unimplemented: `use-syslog` (would divert the logs FortiVPN GUI parses for OTP prompts, certificate failures and interface detection), `-q` (same reason), `ppp-system` (FreeBSD-only) and `pppd` (only recognised by builds without pppd support).
- **Dead code removed.** The unused `verify_cert` and `otp` profile fields and the unused `initd` and `sudopresenv` settings are gone, along with their `main.conf` and profile INI entries.

### Upgrade notes

- Existing profiles with `persistent = true` (or `persistent = 1`) in `~/.fortivpngui/vpnprofiles/*.conf` are read as **60 seconds**, so current behaviour is preserved on upgrade. Set the field to `0` in the editor to stop auto-reconnecting.
- Profiles that never had the option keep **`0`** (no auto-reconnect), which is the new default for new profiles.
- The old `pppd_no_peerdns` key never reached `openfortivpn`, so peerdns was off regardless of its value. Existing profiles therefore load with **Use peerdns** off, preserving current behaviour; the key is still written (inverted) for OpenFortiGUI compatibility.
- Unchecking **Set DNS** now really disables `set-dns`. If a profile relied on DNS being configured while the box was unchecked, tick it again.
- `verify_cert` is no longer written to profile INI files and `initd` / `sudopresenv` are no longer written to `main.conf`. Nothing read them; OpenFortiGUI treats the missing keys as their defaults.

### From 0.2.1

- **VPN log windows** follow the active UI theme (dark / light / system) and refresh when the theme changes.
- **Changelog dialog**: fixed height with vertical scroll for long release lists.
- **Production build**: Vite splits React and Material UI into separate chunks.

### From 0.2.0

- **Internationalization (i18n)**: English, Portuguese, Spanish, French, Italian, German; **Settings → GUI → Language**; `gui/language` in `main.conf`.
- **Light theme** and header toggle (**dark** / **light** / **system**); `gui/theme_mode` in `main.conf`.
- **FortiGate OTP**: one prompt per reconnect cycle; invalid OTP offers disconnect or a new code.
- **`.deb` install/upgrade**: postinst stops instances and clears `~/.config/fortivpngui` (Electron cache); VPN data in `~/.fortivpngui/` is kept.

## Requirements

- **Linux** with `openfortivpn`, `ppp`, and `sudo`.
- **`.deb` install**: also **`libsecret-1-0`** for optional OS credential storage.
- **`.rpm` install**: also **`libsecret`** for optional OS credential storage.

## Install

### Debian / Ubuntu

```bash
sudo apt install ./fortivpngui_0.3.0_amd64.deb
```

### Fedora / RHEL

```bash
sudo dnf install ./fortivpngui-0.3.0.x86_64.rpm
```

### openSUSE

```bash
sudo zypper install ./fortivpngui-0.3.0.x86_64.rpm
```

Then review or tighten the sudoers drop-in if needed:

```bash
sudo visudo -f /etc/sudoers.d/fortivpngui
```

## Build from source

```bash
npm ci
npm run dist        # .deb + .rpm
npm run dist:deb    # .deb only
npm run dist:rpm    # .rpm only (needs rpmbuild / rpm-build installed)
```

Artifacts are written to `release/`.
